Goal: **Launch the user's personally dumped Switch 2 backups and eventually Switch 1 backups directly from SD on a physical Switch 2**, with usable graphics, input, audio, saving, and future broad compatibility. User wants progress toward working games, not open-ended tracing. User hoped for both types of games the next day; this cannot be promised on present evidence.

NUP has its own logger; do **not** insist only gameplay log exists when testing a .nup. Old save paths used `SD:/switch/nx2-backup-loader/saves/`, and earlier Yoshi used `yoshi-demo`; **not auto-migrated**. Current game save folder is based on game display name, so renaming the folder changes the save path.

`build-nup.bat` is separate from `build.bat`. It packs each immediate game folder under `extracted/` to `nups/*.nup`, using `tools/pack_nup_fast.py` and upstream `a55uka/nup` meow branch with `zstandard`. It does not overwrite output automatically. Larger-than-16-MiB files use raw storage to permit fast seeks. `py -m nup.cli verify --fast` is structural validation; not gameplay proof.

A NUP in this project is an **experimental NUP v1 format**, not an encrypted NSP/XCI, and not a standard Switch 2 installation package. The current loader uses extracted/decrypted ExeFS modules and RomFS or compatible NUP. Updates/DLC are **not** layered into an arbitrary base game. Standalone update flag bit 0 is special; missing base is a hard refusal, correctly so.

## 4. Exact latest hardware facts (OOT) and root-cause uncertainty

- Crash(2) 2026-11-21: at ~7.839 seconds, `main_entered=1`, `rpc_calls=835`, `rom_bytes=174856394`, `frames=0`, `fault_state=0`, `host_abort=guest_abort=0`, `ipc=808/808`, `stage=10`. Guest continues significant ROM reads through late startup.
- `GUEST_FS_READ` reaches 605 enters / 602 returned at 7.254 sec; 3 in flight is unsurprising with concurrent readers. `last_result=0` refers to the last completed read.
- `GUEST_CALLSITE name=rom_storage_read caller=0xD5ECD10 module=3 offset=0x11BD10` is real SDK callback site, not crash PC.
- `SAVE_GATE_PROGRESS phase=1` then `phase=2 result=0 caller=0xBE20C14`. The current `bridge.c` defines phases: 1 entrance, 2 register_fs complete, 3 RPC_SAVE_MOUNT complete, 4 final RPC_LOG complete. Final gameplay log says `SAVE_MOUNT_GATE_RETURN`, so do **not** infer process died at phase 2. The snapshot was earlier.
- `NVN_INIT device 0/0` means the *device initialize wrapper was never entered*, not 'device init failed'; queue/window initialization succeeded.
- `RPC_TRAIL result=0x2F5E02 phase=1` is a placeholder, not kernel error; pending requests may complete. `IPC_WATCHDOG started=ended` only refers to monitored calls and sample time.
- CPU exception handler is within the host process. It can miss direct kernel termination and GPU faults. Host `fopen/fflush` independent crash log survives to last completed snapshot but is not an OS crash dump.
- Display/app lifecycle: host calls `consoleExit`, `nwindowReleaseVi2Layer`, `appletExit` before guest worker. This may alter which display/lifecycle services guest code can use; **a possible cause only**. Do not change all lifecycle paths and graphics routes together.
- Audio `0xF601` on specific `aud:u` handles preceded other successful traffic, so needs targeted protocol comparison, not blind filtering.
- Historical OOT `main + 0x10ADBC8` `CMP x0,x8` then conditional branch is **unpatched in latest control**. Old `SDK_BREAK` caller + `0xBC03C` was an earlier distinct failure signature. Do not bypass asserts.

## 6. What 'universal fix' should mean in this project

A universal fix is possible **if** one failure is a common OS/SDK contract issue (example: thread TLS corruption, service session lifetime, applet/display ownership, missing widely used SVC semantics). Implement that at a shared boundary and measure Yoshi, OOT and a third title. It will not solve titles with fundamentally different graphics generations, unavailable kernel privileges, hardware features or incompatible host process constraints. A generic loader requires an honest compatibility matrix even if the universal core is solid.

Architecture target:
1. **Common front end**: game discovery, version/region/profile, file integrity, logs, launch UI, asset cache, save isolation.
2. **Per-OS runtime backends**: Switch 2 native guest SDK/NVN2; Switch 1 guest SDK/NVN plus OS compatibility for running on Switch 2. Use detected NPDM/SDK version, not title-name hacks.
3. **Kernel/process capability broker**: real permission and service support checks. When a required privilege/service is absent, diagnose and refuse; don't spoof 'success' on meaningful operations.
4. **Graphics subsystem**: correct NVN/NVN2 API, GPU driver sessions, memory aliases, fences, window acquisition, compositor ownership and actual presentation.
5. **Declarative title profiles only for exceptional metadata**: any per-game bypass should say why a shared fix isn't yet possible, name build ID and carry a regression test.

## 10. Test matrix schema & acceptance gates

Track each test as: `UTC/local timestamp | branch SHA | NRO SHA-256 | FW | kaiHEN commit | ounce-devkit version | guest title ID/version/build IDs | extracted/NUP hash | SD location | success to nnMain | successful RomFS mount | save mount result | NVN queues/window/acquire/submit/present | frames | audio/input | final error / exit | saved logs`.

**Success gate 1:** same build runs Yoshi demo to a real visible frame after instrumentation.
**Gate 2:** OOT crash reason is isolated to one reproducible SDK/service/process lifecycle failure with *objective evidence*, not guessed from last line.
**Gate 3:** a fix removes that failure and reaches a real OOT frame without special-casing unrelated titles.
**Gate 4:** third independent Switch 2 title reaches meaningful play with saves/audio.
**Gate 5:** Switch 1 test title reaches a frame **through a separately validated Switch 1 compatibility backend** on Switch 2 hardware.
Do not call overall project compatible before actual tests. The loader itself cannot grant arbitrary missing process-level kernel rights.
