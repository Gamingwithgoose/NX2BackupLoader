Offline original-startup experiment (specific supplied Yoshi demo build)

Requirements: Node.js, Python with unicorn 2.1.4, Windows x64 LLVM/Visual Studio
for the C parity harness, and the decoder from SebaaMG/ns2jb-modloader at
50d473e341bb0af3134098bd4c4223f8239ffdd8 (lib/exefs.cjs and its dependencies).
The decoder source is https://github.com/SebaaMG/ns2jb-modloader . No third-party
JavaScript decoder is copied into this repo. The console uses its supplied C
decoder instead. All six original NSO SHA256 hashes must match this Yoshi build.

Run from the probe directory, writing decoded images outside the repo:
node tests/export-startup.cjs PATH/TO/lib/exefs.cjs PATH/TO/Yoshi/base/exefs PATH/TO/SCRATCH
python tests/trace-startup.py PATH/TO/SCRATCH

In an x64 Visual Studio developer shell with LLVM clang-cl on PATH:
clang-cl /O2 /MD /D_CRT_SECURE_NO_WARNINGS tests/native_parity.c source/module.c source/nso.c source/zbic.c /Fe:native_parity.exe /link bcrypt.lib
native_parity.exe PATH/TO/Yoshi/base/exefs PATH/TO/SCRATCH

The exporter writes decrypted game images and metadata only to SCRATCH. Do not
redistribute those images. No console or external service is contacted.

Experiment:
- Place the six verified images at the tested module addresses in Unicorn.
- Enter the original rtld with a synthetic initial thread handle and TLS region.
- Model QueryMemory from the supplied segment layouts. Emulator memory itself is
  mapped permissively; this does not test memory permissions or PAC enforcement.
- Accelerate rtld's memset and model PAC returns without validating signatures.
- Capture images when the original rtld relocation pass completes, before SDK
  startup. Continue into the SDK with deterministic entropy and synthetic process
  information; stop before the first unmodeled kernel request.
- Resolve all 641 main PLT entries using the original rtld's lazy binding function.
- Apply our actual C linker to the same six images at matching virtual addresses.
  Preserve only subsdk0's exact zero anonymous TLS pair, using the production
  policy interface. The default strict policy must still reject this image set.
- Compare all relocation destinations against original-rtld snapshots.

Observed: 2,691,120 destinations, zero differences after resolving lazy imports.
The trace reaches sdk+0x180d18 GetInfo(type=29, current-process, sub=0), where
execution stops before forwarding or fabricating that unknown request. Earlier
known GetInfo replies are synthetic and listed in startup-validation.json.
This is a limit of the emulator model, not a claim that the console rejects it.

The original rtld skips the anonymous TLSDESC relocation in its dispatch pass.
The runtime callback at subsdk0+0xb4b3c reads that zero pair if invoked. Its safe
use is NOT established. The console probe never calls it or the SDK startup.
Full startup, RomFS redirection, kernel/heap compatibility and save isolation
still require implementation. No gameplay has been demonstrated.

Offsets and fixed model addresses are build-specific, not general launch APIs.
Reproduction may fail if Windows cannot reserve the model addresses; the C
harness exits rather than overwriting an existing mapping. Captured validation
is supplied without decrypted game bytes.

Suite 0.3 hardware observations and replay are recorded in HARDWARE-03.txt.
Use --process-report or --process-info-json to replay observed GetInfo replies.
The retained hardware replay passes type 29 and stops at GetThreadPriority.
